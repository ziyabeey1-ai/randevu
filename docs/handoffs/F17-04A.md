# F17-04A — MVP kabul preflight

Bu dilim F17-04 kabulünü **yapmaz**. Amacı, birleşik release kabulüne geçerken yapısal bir sahte-yeşil üretilememesidir.

## Sözleşme

- Canlı kabul kaynağı mevcut `MVP_ACCEPTANCE.md` dosyasıdır; ikinci bir durum tablosu açılmaz.
- M01…M31 tam ve tekil olmalıdır.
- F17-04 release modu M23 hariç 30 senaryoyu `Geçti` ister.
- M23 yalnız F17-05 gerçek pilotunda G17 kapanışına katılır.
- G17 modu 31/31 `Geçti` ister.
- Release/G17 kontrolü exact 40 karakter commit SHA'sı olmadan çalışmaz.
- `docs/references/README.md` içindeki 11 referans ekranın tamamı benzersiz ve repo içinde mevcut olmalıdır.
- `Bekliyor`, `Kaldı` veya `Engelli` kabul değildir.

## Komutlar

Yapı envanteri:

```sh
node scripts/f17-acceptance-preflight.mjs --mode=inventory
```

F17-04 release kapısı, senaryolar gerçek release adayı üzerinde yürütülüp matrise kanıtlarıyla işlendiğinde:

```sh
F17_RELEASE_SHA=<exact-release-sha> node scripts/f17-acceptance-preflight.mjs --mode=release
```

F17-05 pilot sonrası G17:

```sh
F17_RELEASE_SHA=<exact-release-sha> node scripts/f17-acceptance-preflight.mjs --mode=g17
```

## Sınır

Bu script tarihsel task/PR/CI sonuçlarını Mxx senaryosu yerine geçirmez. Gerçek mobil cihaz, iki eşzamanlı istemci, görsel değerlendirme, hosted sağlayıcı ve pilot kanıtını üretmez. Sadece kabul matrisinin eksik satır, yanlış statü, pilot bağımlılık döngüsü veya eksik referans ekranıyla yanlışlıkla kapanmasını engeller.
